# AudioFixSkill · 低质量 Live 音频修复

把低质量的现场录音修复到接近录音室的听感。适用于演唱会歌曲、MC（舞台讲话），以及两者混在一起的整场录音。

它不是"一键套效果"，流程是：

1. **判断**：测量哪里坏了，每个结论都附测量数字。
2. **计划**：按证据生成一份能人工修改的修复计划，每一步都写明"为什么"。
3. **修复**：按计划渲染。
4. **验证**：用客观指标检查，再生成响度对齐的 A/B 试听文件交给人耳确认。

它是一个 AI skill，Claude、ChatGPT、Codex、Gemini、Cursor 等都能用；也是一个普通的命令行工具，没有 AI 也能直接跑。

> skill 本体在 [`skills/live-audio-restore/`](skills/live-audio-restore/)。AI 读 [`SKILL.md`](skills/live-audio-restore/SKILL.md)，人读这份 README 就够了。

## 适用素材

- **来源**：电视/广播转录、B 站/YouTube 搬运的老演出、观众席手机或录音笔录音。
- **歌曲的问题**：
  - 过度压限：糊成一片，鼓没有冲击力。
  - 反相层：相位怪，手机外放时某个乐器消失。
  - 音色问题：闷、刺耳、单薄。
  - 编码器砍掉的高频：16 kHz 以上一片空白。
  - 交流哼声、削波。
- **MC 的问题**：
  - 讲话声音小。
  - 观众欢呼盖过讲话。
  - 混响重、低频轰鸣。
  - 经过扩声（PA）后人声单薄。

**换一个 AI 用，结果也一样好。** 上表那首动态正常的观众席录音，加入新规则之前曾由两个 AI 分别用本 skill 手动调参修复：

| 版本 | 音色偏差 | 响度范围 | 响度 |
|---|---|---|---|
| Claude | 1.80 dB | 6.4 LU，起伏被压平 | -13.0 LUFS |
| ChatGPT | 2.26 dB | 9.0 LU | -16.0 LUFS，比原版还小声 |

**可复现性。** 第一行那段音频此前做过一版手工精修，也就是本 skill 的原型。现在用 skill 全自动重跑，结果与手工版几乎一致：

| | 手工精修版 | skill 自动结果 |
|---|---|---|
| 响度 | -10.61 LUFS | -10.61 LUFS |
| 峰值/响度比 | 9.52 dB | 9.51 dB |
| 3 秒峰值因数 | 12.27 dB | 12.25 dB |
| 长期频谱差（50 Hz–16 kHz） | — | 0.13 dB RMS |

## 安装

```bash
git clone https://github.com/Felix-Chang-67/AudioFixSkill.git
cd AudioFixSkill/skills/live-audio-restore
bash scripts/setup.sh          # 装好缺的东西，最后自动运行 check
```

- **必需**：Python 3.9+。**推荐**安装 ffmpeg。
- **setup.sh 会装的组件**（全部能在 CPU 上跑）：

  | 组件 | 用途 |
  |---|---|
  | numpy / scipy / numba | 信号处理 |
  | demucs + PyTorch | 音轨分离，分成人声/鼓/贝斯/其他 |
  | De-limiter | 神经网络去压限 |
  | faster-whisper | 用词级时间戳定位 MC 讲话，并做可懂度检查 |
  | Apollo（可选） | 修复低码率编码造成的高频损伤，让高频不再发假发刺。有 NVIDIA 显卡（CUDA）或 Apple 芯片（MPS）时自动用显卡，快很多；显卡出错会自动退回 CPU。只用 CPU 约为音频时长的 6 倍，5 分钟的歌约半小时 |

- **缺组件时**：缺哪个就自动降级。`python3 scripts/audiofix.py check` 会告诉你少了什么、会影响什么。
- **测试环境**：Python 3.13、torch 2.15、demucs 4.1.0、faster-whisper 1.2.1、numpy 2.5、scipy 1.18、ffmpeg 6.1。
- **只用 CPU**：可以先装 CPU 版 PyTorch，省磁盘空间。

## 快速开始

```bash
python3 scripts/audiofix.py auto 歌曲.m4a --work out --content music    # 一首歌
python3 scripts/audiofix.py auto MC.m4a --work out --content speech    # 一段 MC / 讲话
python3 scripts/audiofix.py auto 整场.m4a --work out                   # 歌和 MC 混在一个文件里：自动分段
```

用户说了文件是歌还是 MC，就用 `--content` 直接指定，比自动判断可靠。只有歌和 MC 混在一个文件里时才需要自动分段。

`out/` 里会有：

| 文件 | 内容 |
|---|---|
| `diagnosis.md` | 判断报告：哪里坏了，附数字 |
| `overview.png` | 频谱图、响度和立体声宽度随时间的变化，标出歌曲/MC 分段 |
| `plan.json` | 修复计划，每一步都有 `why` |
| `restored.wav` | 修复结果，24-bit / 44.1 kHz |
| `restored.m4a` | AAC 256k 副本，方便手机听 |
| `verification.md` | 验证报告：每项检查 PASS/WARN，附修复前后数字 |
| `AB.wav` | 同一段先放原版再放修复版，每对响度对齐，**先听这个** |
| `compare.png` | 修复前后与参考的长期频谱对比 |

分步运行，可以先看计划再修：

```bash
python3 scripts/audiofix.py analyze 演出录音.m4a --work out     # 判断 + 生成计划
# 看 out/diagnosis.md，必要时改 out/plan.json
python3 scripts/audiofix.py restore --work out                  # 修复 + 验证
python3 scripts/audiofix.py restore --work out --set music.match.hi_db=3   # 改一个参数重渲染
```

**音色参考决定什么叫"好"。** 内置的 `jrock_band` 是吉他乐队、现代响度母带的统计数据。想要"像专辑"，最好的参考是这首歌自己的录音室版；其次是同一艺人的录音室音轨：

```bash
# 这首歌自己的录音室版（最好）：iTunes 官方 30 秒试听，需要联网，只保存统计数据，不保存音频
python3 scripts/audiofix.py profile --name mysong --itunes-artist "艺人名" --itunes-song "歌名" --country jp --out mysong.json
# 该艺人的录音室音轨
python3 scripts/audiofix.py profile --name myband --files a.flac b.mp3 c.m4a --out myband.json
# 或者该艺人的多首试听片段
python3 scripts/audiofix.py profile --name myband --itunes-artist "艺人名" --country jp --out myband.json
python3 scripts/audiofix.py auto 演出录音.m4a --work out --music-profile mysong.json
```

在一份观众席录音上，用 27 首歌的平均做参考时，100–400 Hz 比这首歌的录音室版少 5–12 dB；换成这首歌自己的试听片段，差距缩小到 ±3 dB 以内。

## 怎么判断（两条路径）

先测全局，再把文件分成"歌曲 / MC / 间隙"，然后对每类内容分别判断。完整的阈值、听感对应和例子见 [`references/diagnosis.md`](skills/live-audio-restore/references/diagnosis.md)。

### 内容分段：哪里是歌，哪里是 MC

| 依据 | 歌曲 | MC |
|---|---|---|
| 节奏组（鼓+贝斯）能量占比 | 高 | < 8 % |
| 人声中的停顿比例 | 唱歌约 5 % | 说话约 45 % |
| Whisper 每秒识别到的词 | — | ≥ 0.6 个/秒 |

自动分段的弱点是没有鼓的安静唱段：唱歌在乐句之间也会停顿，Whisper 也会把歌词当成词听写出来，所以可能被误判成 MC。知道文件是什么时，用 `--content` 指定即可。

最短片段：歌曲 20 秒、MC 10 秒，更短的并入相邻片段。音乐内部的"分区"只在录音链路的立体声像突变处切（比如转播换了信号源），不在换歌处切。

### 全局问题

| 测量 | 阈值 | 听感 | 触发的修复 |
|---|---|---|---|
| 平顶连续段 | ≥ 20 次/分钟 | 削波，炸音 | 去削波 |
| 50/60 Hz 及谐波高出频谱 | 基波 ≥ 10 dB，或两个谐波 ≥ 8 dB | 嗡嗡声 | 陷波去哼声 |
| 截止频率处的陡降 | > 25 dB 且截止 < 18.5 kHz | 发闷，没有空气感 | 高频重建 |
| 截止频率以下的高频质感（频谱平坦度） | 截止 < 16 kHz，且 8–12.5 kHz 平坦度 < 0.15（受损的约 0.06–0.07，正常的 0.28–0.41）；不管截止是陡墙还是带过渡的低通 | 高频发假、发刺、像金属 | 先用 Apollo 修复质感，再重建高频，其中一半换成同包络的噪声质感 |

### 音乐路径

| 测量 | 阈值 | 听感 | 触发的修复 |
|---|---|---|---|
| 响度范围 LRA、峰值/响度比 PLR | LRA < 4 LU 或 PLR < 11 dB 为被压限过；LRA < 2 或 PLR < 9.5 为重度 | 糊、累耳朵、鼓没冲击力 | 被压限过：神经网络去压限（深度 1.5 或 2 倍）、分轨控峰、母带做响。**没被压限过（动态正常）**：轻压缩、按原版还原整首起伏、限幅器几乎不工作，保住现场的动态 |
| 每个分离音轨的反相：① 4 秒窗口 L/R 相关性 < -0.3 的能量占比；② 修复器检测到的相干反相能量 + 单声道损失 | ① ≥ 10 %（整层反相），或 ② ≥ 5 % 且单声道损失超过 1 dB（只有部分频段反相） | 相位怪，手机外放少了乐器 | 只旋转相干反相的频点，不整轨翻转 |
| 鼓轨的左右声道相关性 | ≥ 0.8 是混音过的画面；< 0.8 是房间拾音，本身已经很宽 | 太宽、发散 | 只给混音过的画面加宽 |
| 各轨的声场宽度（侧声比中声） | 房间拾音时人声、鼓、贝斯会像房间一样宽 | 不聚焦、不纯净、人声发飘 | 人声、鼓、贝斯收窄到录音室版对应轨的宽度（最多收 20 dB），吉他保持宽 |
| 人声占 3–10 kHz 能量的比例，5–8 kHz 与参考的偏差 | ≥ 50 % 或 > +4 dB 时去齿音最多 9 dB，否则 6 dB | 齿音、刺耳 | 去齿音 |
| 长期频谱与参考的偏差（逐频带） | 越大越需要校正 | 闷、浑、薄、刺 | 分轨音色匹配 60 %，整体匹配 85 % |
| 各音轨相对整体的电平与参考比 | 差异大就调 | 人声太前/太后、贝斯太弱 | 向参考比例移动一半，最多 ±3 dB |
| 立体声类型 | 立体声才加宽 | — | 单声道不做假立体声 |

### MC 路径

| 测量 | 阈值 | 听感 | 触发的修复 |
|---|---|---|---|
| 句间间隙相对讲话的电平（中位数） | > -8 dB 时，观众在和讲话抢 | 欢呼盖过讲话 | 间隙中压住观众，讲话帧最多动 1.5 dB |
| 人声/背景比 | < 6 / < 15 / < 25 / ≥ 25 dB | 底噪、嘈杂 | 平稳降噪 10 / 8 / 6 / 0 dB |
| 80 Hz 以下能量相对 200–800 Hz | > -12 dB 为轰鸣 | 低频隆隆声 | 高通 100 Hz（否则 75 Hz） |
| 分离后人声轨保留了多少讲话（vocal_share） | < 0.3 说明分离把人声丢了 | — | 改用整体混音处理 |
| 人声频谱与目标的偏差 | 目标按优先级取：同一文件里有歌 → 歌曲人声轨的 EQ；否则 → 参考的录音室人声（400 Hz 以上）+ 语音平均谱（250 Hz 以下）；再否则 → 语音平均谱 | 单薄、发闷、"喇叭味"、没有空气感 | 和第二版修人声一样：向目标移动 85 %，只在人声占主导的频段提升，提升最多 +3 dB |
| 讲话部分的峰值/响度比 | 同一文件里的歌被测出转播限幅器，且讲话 < 11 dB | 讲话也被压扁 | 去压限（深度 1.5） |
| 截止频率处的陡降（转播） | > 25 dB 且截止 < 18.5 kHz | 讲话比歌更闷 | 高频重建，比歌曲温和 3 dB |
| 讲话人定位 | 优先 Whisper 词级时间戳；没有 Whisper 时用浊音检测（准确率约 80 %） | — | 决定"哪些帧是讲话"，后续每一步都依赖它 |

## 怎么修（两条路径）

每一步的原理、参数和失败模式，见 [`references/music-path.md`](skills/live-audio-restore/references/music-path.md) 和 [`references/speech-path.md`](skills/live-audio-restore/references/speech-path.md)。

### 音乐路径

1. **基础修复**：20 Hz 高通、去哼声、去削波。低码率素材先用 Apollo 修复被编码器弄稀疏的高频质感。
2. **神经网络去压限**（只用于被压限过的素材）：用 De-limiter 的增益曲线，按 1.5–2 倍深度作用在每个音轨上。
3. **反相修复**：整层反相的音轨、只有部分频段反相的音轨都修，只旋转相干反相的频点。
   - 房间拾音的录音还会做声场匹配：人声、鼓、贝斯收窄到录音室版对应轨的宽度。
4. **分轨处理**：人声去齿音，鼓的瞬态恢复，吉他/键盘层加宽（只用于混音过的立体声画面）。
5. **分轨音色匹配**：每个音轨向参考里的同一音轨移动 60 %，按分区进行。
6. **音轨平衡**：向参考比例移动一半。
7. **分轨动态**：鼓轨单独削峰；贝斯、人声、吉他各自压缩；总线粘合。
   - 被压限过的素材处理得较重，这样主限幅器不会带着整个混音"抽吸"。
   - 动态正常的素材处理得很轻：鼓峰只在鼓轨响度之上 15 dB 处才削，压缩比 2:1 / 1.5:1，不做总线粘合。
8. **整体音色匹配**：85 %，8191 抽头线性相位 FIR。
9. **高频重建**：在编码器截止频率以上，用单边带频移从下方频段重建，其中一半换成同包络的噪声质感（真实的空气感是细密的，不是稀疏的金属声），并校准到参考的高频斜率。
10. **低频单声道化**：100 Hz 以下合成单声道。
11. **还原整首起伏**（只用于动态正常的素材）：处理完以后，把原版每 3 秒的响度轮廓放回去，安静的前奏、间奏保持安静。
12. **感知响度母带**：找到限幅器超过 1 dB 和 2 dB 的时间都不超标的最响电平，真峰值 -1 dBTP。
    - 被压限过的素材：标准是 8 % / 1.5 %，做到现代母带的响度。
    - 动态正常的素材：标准是 2.5 % / 0.5 %，限幅器几乎不工作，并且不会比原版更小声。

### MC 路径

讲话人的声音按音乐路径第二版处理人声轨的方式来修，目标是听起来和修复后歌里的人声一致。想要更轻、更自然的处理，可以用 `speech.mode=gentle` 切回原来的方式。

1. **定位讲话人**：Whisper 词级时间戳；语言由前三候选分别解码打分决定，避免误判。
2. **取声源**：人声取自分离的人声轨，现场氛围放在下面（-6 到 -12 dB），保留"在现场"的感觉。
3. **去压限**：只在同一文件的歌曲测出转播限幅器、且讲话的峰值/响度比也低时才开。
4. **平稳降噪**：ffmpeg afftdn，6–10 dB。**不用神经网络降噪**，它会把经过 PA 的混响讲话一起删掉。
5. **高通**：75 或 100 Hz。
6. **人声音色**：和第二版修人声一样，向目标移动 85 %，只在人声占主导的频段提升（不连带抬高欢呼），提升最多 +3 dB。目标按优先级取：
   - 整场录音里有歌：直接套用歌曲人声轨的 EQ。同一支麦、同一套扩声和转播链路，修正量相同，讲话人听起来就是修复后歌里的那个声音。
   - 单独的 MC：400 Hz 以上向参考的录音室人声靠，250 Hz 以下按语音平均谱。说话比唱歌低，录音室人声在 200 Hz 以下几乎是空的，全按它来会把讲话削薄。
   - 有同一场演出的歌曲录音：先修歌，再用 `speech.match.chain_file` 把它的人声 EQ 套到 MC 上。
7. **动态**：去齿音，第二版的人声压缩器（3:1，4/90 ms），慢速电平平衡。
8. **压住句间欢呼**：讲话本身几乎不动。
9. **高频重建**：转播素材有编码器截止时才开，比歌曲温和 3 dB。
10. **响度**：纯 MC 文件 -16 LUFS；整场录音中 MC 比音乐低 4 dB。

### 怎么验证

- **自动检查**：每项给出 PASS/WARN 和修复前后数字。
  - 真峰值、没有新削波。
  - 音色更接近参考、动态没有被进一步压扁、中频没有残留反相、单声道兼容。
  - MC 欢呼已在讲话之下、Whisper 识别讲话不比原来差。
- **人耳确认**：`AB.wav` 是响度对齐的原版/修复版对比，避免"更响 = 更好"的错觉。

用户听完后的反馈怎么对应到参数（"太闷""太刺""低音太多""欢呼没了不像现场"……），见 [`references/tuning.md`](skills/live-audio-restore/references/tuning.md)。

## 局限（实话实说）

- **高频重建是推算，不是复原。** 编码器丢掉的信息找不回来，重建的高频是从下方频段推算出的"合理的"高频。
- **讲话时同时出现的欢呼去不掉。** 动它就会伤到人声。只能压句与句之间的欢呼。
- **音轨分离有串音。** 单个音轨改得太狠会出现"水声"，默认参数已经收敛过。
- **"好"由参考决定。** 参考选错风格，结果就会往那个风格靠。尽量用同一艺人的录音室音轨建参考。
- **单声道素材不会被做成假立体声。**
- **AI 听不到声音。** skill 要求 AI 只汇报测量到的变化，最终由人听 `AB.wav` 判断。
